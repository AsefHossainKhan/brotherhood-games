# Fix Critical Game Continuity Blockers

## Problem
The game breaks after the first hand: SCORING phase shows the lobby instead of the game board, there's no way to trigger the next hand, and no rematch flow exists.

## Root Causes
1. `page.tsx` line 52 — `isPlaying` check excludes `SCORING` and `MATCH_COMPLETE` phases
2. `gameHandlers.ts` — no `START_NEXT_HAND` socket listener
3. `useGame.ts` — no `startNextHand()` action
4. No SCORING/MATCH_COMPLETE UI panels exist

---

## Changes

### 1. Fix `isPlaying` check — `frontend/src/app/room/[code]/page.tsx`
Add `SCORING` and `MATCH_COMPLETE` to the phase list on line 52:
```ts
const isPlaying = status === 'playing' || ['PLAYING','BIDDING','TRUMP_SELECTION','SECOND_DEAL','DOUBLE_PHASE','SCORING','MATCH_COMPLETE'].includes(phase);
```

### 2. Add `START_NEXT_HAND` backend handler — `backend/src/socket/handlers/gameHandlers.ts`
Add after the existing action handlers (~line 91):
```ts
socket.on('START_NEXT_HAND', () => handleAction('START_NEXT_HAND'));
```
This works because `handleAction` delegates to `runtime.handleGameAction`, which calls `engine.handleAction` → `handleStartNextHand` → `prepareNextHand`. The `room.status` check (`'playing'`) passes because during SCORING the status is still `'playing'` (only `MATCH_COMPLETE` sets it to `'finished'`).

### 3. Add `startNextHand()` to frontend hook — `frontend/src/hooks/useGame.ts`
Add the action and export it:
```ts
const startNextHand = () => {
  socket?.emit('START_NEXT_HAND');
};
```
Include `startNextHand` in the return object.

### 4. Add `CALL_BID` backend handler — `backend/src/socket/handlers/gameHandlers.ts`
The frontend emits `CALL_BID` but no backend listener exists. Add:
```ts
socket.on('CALL_BID', () => handleAction('CALL_BID'));
```

### 5. Create ScoringPanel component — `frontend/src/components/games/twenty-nine/ScoringPanel.tsx`
New component shown during `SCORING` phase. Displays:
- Hand result (who won, trick points, bid success/fail)
- Updated scores
- "Next Hand" button (only for the host)
- If match is over (`MATCH_COMPLETE`), show winner announcement + "Play Again" note

### 6. Create MatchCompletePanel component — `frontend/src/components/games/twenty-nine/MatchCompletePanel.tsx`
New component shown during `MATCH_COMPLETE` phase. Displays:
- Final winner announcement
- Final scores and sets
- "Back to Lobby" button that navigates to home (no rematch yet — room is finished)

### 7. Wire panels into GameBoard — `frontend/src/components/game/GameBoard.tsx`
Add imports and conditional rendering:
```tsx
const showScoringPanel = phase === 'SCORING';
const showMatchCompletePanel = phase === 'MATCH_COMPLETE';
// ... in JSX:
{showScoringPanel && <ScoringPanel />}
{showMatchCompletePanel && <MatchCompletePanel />}
```

### 8. Handle `GAME_FINISHED` in useSocket — `frontend/src/hooks/useSocket.ts`
Update the `GAME_FINISHED` handler to clear game state and room so the user returns to a clean state:
```ts
socket.on('GAME_FINISHED', (data) => {
  console.log('Game finished:', data.winner, data.reason);
  // Room status becomes 'finished' via ROOM_UPDATED, lobby will render
});
```
The `ROOM_UPDATED` event already sets `status: 'finished'`, which causes `isPlaying` to become false and the lobby to show. But we keep the game board visible during SCORING/MATCH_COMPLETE via the phase check, so this only fires as a fallback.
