# UI Revamp — Brotherhood Games

## Context

The game is fully functional (201 unit tests, 5 marriage E2E tests, all passing) but the UI is "functional but bland" — flat dark background, opponents shown as cards-in-a-row, no table feel, basic SVG cards, no animations. The user wants:

1. **Card table layout** — players sitting around a table (like real card games)
2. **Opponent cards shown** — card backs visible for each opponent, not just "8 cards" text
3. **Card rearrangement** — drag-and-drop to reorder hand
4. **Better card assets** — either improved SVGs or free image assets
5. **Animations** — dealing, playing, hover/select effects

## Approach: Hybrid SVG + Free Assets

### Card Assets Strategy
We'll keep our SVG approach but **significantly upgrade** the rendering. Pure SVG is actually ideal for this because:
- Scalable at any resolution
- Easy CSS hover/select transforms
- No HTTP requests for image files
- No CORS or asset hosting concerns
- Consistent across all platforms

**Plan:** Enhance the existing SVG cards to look like realistic playing cards — proper suit rendering, better typography, realistic card proportions, improved card back design. The current SVGs are 100 lines each and very basic. We'll make them look like actual Bicycle-style cards.

For future enhancement (Phase 5+): downloadable card sprite PNGs as an option via settings.

### Animation Library
**Framer Motion** — industry standard for React animations. Lightweight, great for:
- Card dealing animation
- Card play-to-table animation
- Hand rearrangement (drag-and-drop with layout animation)
- Page transitions
- Hover/select micro-interactions

### Phase 3: Card Rearrangement (Drag & Drop)
**Goal:** Players can drag cards to reorder their hand.

**Changes:**
- Install `@dnd-kit/core` + `@dnd-kit/sortable` (lightweight DnD library, works great with React)
- `HandArea.tsx` → Full rewrite with DnD
  - `DndContext` + `SortableContext` wrapping the card list
  - Each card wrapped in `useSortable()`
  - Cards animate smoothly into new positions
  - Drag overlay shows card being dragged
  - Drop indicator (line between cards)
- `CardComponent` → Add `data-id` prop for DnD identification
- State: Store card order in local component state (or persist to `settingsStore`)

**New dependencies:**
- `@dnd-kit/core` (^6.0.0)

### Phase 4: Animations
**Goal:** Smooth, professional animations throughout the game.

**Changes:**
- Install `framer-motion` (^12.0.0)
- **Card dealing:** Cards animate from center of table to each player's hand
  - Staggered animation (0.1s per card)
  - Cards fly out from deck position, then flip to reveal
- **Card play:** Cards animate from hand to table center
  - Card lifts from hand, shrinks and moves to table position
  - Previous trick cards slide out before new trick
- **Trick collection:** Won trick cards animate to winner's area
  - Cards slide toward winner, shrink, and disappear
- **Phase transitions:** Panels slide in/out (bid panel, scoring, etc.)
- **Turn indicator:** Subtle pulse/glow on active player's seat
- **Score changes:** Numbers animate when scores update
- **Card hover:** Scale up slightly on hover (desktop)
- **Card select:** Lift up with enhanced shadow on select

**New dependencies:**
- `framer-motion` (^12.0.0)

**Files to modify:**

## Key Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Card assets | Enhanced SVG (not images) | Zero HTTP requests, infinite scalability, easy animations, no hosting |
| Animation library | Framer Motion | Industry standard, excellent React integration, layout animations for DnD |
| DnD library | @dnd-kit | Lightweight, accessible, great SortableContext for card reordering |
| Table layout | CSS positioning (not Canvas/WebGL) | Simpler, React-friendly, accessible, Tailwind-compatible |
| Card back | Keep SVG, enhance design | Consistent with card faces, no additional assets |

## Risk: Breaking E2E Tests

The E2E tests rely on specific DOM structure (`data-testid` attributes) and text content. Phases 1-4 will change visual rendering but should preserve:
- All `data-testid` attributes
- All text content used in assertions
- Socket event flow (no backend changes)

Phase 1 layout changes are highest risk for E2E breakage. We should run E2E tests after each phase.
